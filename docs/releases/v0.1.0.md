# v0.1.0

The first minor release of recordprims: the pure-Go `durable-record/v1` store
(`recordprims-fs/v2`) for use in applications, passing all 400 vectors of the
pinned `3leaps/crucible` `v0.2.10` contract.

## Stability

| Surface | Status |
| --- | --- |
| `durable-record/v1` records written by the Go module | Conform to `durable-record/v1` as pinned (`3leaps/crucible` `v0.2.10`), and later recordprims releases keep reading them. The contract itself is proposed and experimental upstream. |
| Go module `github.com/3leaps/recordprims` | Supported. Any breaking API change before 1.0 comes in a new minor release and is listed in the changelog. |
| Local filesystem store format (`recordprims-fs/v2`) | Later 0.x releases open a store written by 0.1.0, or a store-format change ships with a documented migration and a changelog entry. |
| Rust crate `recordprims` | Preview, in the repository and not published. Plain streams only; continuation streams and streams carrying compaction state are refused. |
| Bucket stratum (`internal/stratum/bucketcas`) | Experimental and internal. It has no public API and has not been tested against a cloud storage provider. |
| TypeScript and Python bindings | Planned. |

## What it ships

- **Streams and journal.** `OpenStream`, `Append`, `Retire`, `Protect`,
  `Reconcile`, `Head`, `Revisions` and `Release`, with keyed idempotent writes,
  typed receipts, protection holds, continuations, detached stream seals,
  sealed-continuation compaction and predecessor reclamation.
- **Exact selection on every use.** `UseRequest.Selection` applies to serve,
  export and reuse, so a reader can release one exact revision; a held
  revision is refused for every purpose and a retired record is refused for
  serve.
- **Producer instants.** `NormalizeProducerInstant` and `ProducerInstant` give
  producers the canonical instant spelling before a record digest is
  computed, refusing ambiguous spellings and sub-microsecond values instead of
  repairing them. The Rust crate has the same helpers.
- **Two implementations checked against each other** for the operations the
  Rust crate implements (store root, bodies and plain streams): `make
  crosscheck` runs them through Go and Rust and requires identical bytes, and
  each opens stores written by the other.

Also in the repository: `examples/project-record-writer`, which records project
decisions and updates through the public Go API. It is a separate module, not a
release artifact, with no compatibility promise.

## Not claimed

One store is used from one host on a local filesystem; there is no cloud or
network storage backend. A receipt survives the writer process being killed;
power loss is not claimed.

## Platforms

CI runs `make check` on Linux amd64 and arm64 in the digest-pinned tools
container, `make check-platform` natively on darwin arm64 and windows amd64
and arm64, and builds and tests the Go module standalone outside the
repository. The Go module is cgo-free and needs Go 1.26 or later.
